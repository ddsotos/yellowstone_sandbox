# Value search speedup candidates

更新日: 2026-07-25

## 現状

- 候補探索対象:
  - 1枚出し + `EndTurn`
  - 2枚出しで `REFILL` 境界に到達する手
- 現在ある高速化:
  - `0失点2枚手` がある時だけ負カード増加ベース枝刈り
  - adaptive p/q:
    - `negative + loss >= 10` なら `increase <= 4`
    - それ未満なら `increase <= 8`
  - 近似B:
    - 未出色だけ近傍列制限
    - 2枚目は1枚目後の盤面で再計算

## 候補

### 1. 1枚目で上限超えた枝をさらに早く切る

- 1枚目時点の負カード増加で即除外
- 2枚目生成前に切る枝を増やす

### 2. 1枚目候補の事前ランキング

- 0失点
- frame維持しやすい
- heuristic評価が高い
- 色/手札整理が良い

上から見ることで、弱い1枚目の2枚目展開を減らしやすい。

### 3. 2枚目だけ上位K探索

- 各1枚目の後で2枚目全列挙をしない
- 軽い基準で上位KだけCNNへ送る

### 4. CNN前に軽量スコアでふるい

- 負カード増加
- 得点変化
- 0失点2枚か
- 手札整理
- frame収まり

これだけの軽い評価で上位Nへ絞ってからCNN推論する。

### 5. 候補特徴量生成のキャッシュ / 差分更新

- 1枚目後の共通状態を再利用
- board tensor を差分更新
- history/context の共通部分を再利用

### 6. `legal_actions` を探索専用列挙に置換

汎用 `legal_actions(state)` を何度も呼ばず、value探索向けの専用列挙器を作る。

狙い:

- 全合法手の完全列挙は維持
- ただし中間生成物を減らす
- `PlaceCardAction` と frame を探索都合で直接生成する

候補:

- 列単位で先に合法性判定
- cardごとに置ける列だけ出す
- frameは盤面を含む候補だけ先に出す
- 1枚目後の2枚目列挙も同じ専用経路にする
- `EndTurn` 判定を専用化する

### 7. frame単位探索

- まず現在盤面を含む3x3 frame候補を出す
- そのframe内で置ける1枚目/2枚目だけ探索

### 8. CNN推論バッチ最適化

- 候補をより大きくまとめる
- 推論呼び出し回数を減らす

### 9. 近似モードの段階化

- exact
- prune only
- approx columns
- top-K second move

速度/勝率の妥協点を比較しやすくする。

## 現時点のおすすめ順

1. frame単位探索
2. 特徴量キャッシュ / 差分更新
3. `legal_actions` 探索専用化
4. CNN前の軽量ふるい
